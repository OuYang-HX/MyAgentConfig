# gwf-release · 一键发版与交付

## 一句话触发
> "发一版" / "打包交付" / "构建号加一"

## 前置（没有就跳过）
- 代码已按 `gwf-sync` 对齐官方基线，验证通过（`gwf sync --all --verify`）。
- `.gwf.json` 里有 `release` 段（打包命令、产物、版本来源、交付目录）。没有就先补，见 `../../references/templates.md`。

## 它替你决定的事（不用你说条件）

1. **版本号 = 已纳入源码的官方版本**，不是"最新发布标签"，除非两者一致。
2. **构建号单调递增**：`versionCode`/`buildNumber` 必须大于设备已装包和官方包，每次定制交付 +1。
3. **自定义标签只用于显示**（如 `oyhx.7`），比较仍用数字版本。
4. **更新提醒指向官方发布渠道**，不指向个人仓；不按构建时间判断源码新旧。
5. **产物命名**：`<名称>-<版本>-<标签>-code<构建号>-<日期>-<架构>.<ext>`，并生成 `.sha256`。
6. **推送纪律**：`git push --force-with-lease=<ref>:<旧SHA>`，动手前先把旧 SHA 记下来。

## 标准流程

### 1. 基线确认
```bash
git -C main log --oneline -1
git -C main describe --tags --always          # 已纳入的官方发布标签（如有）
gwf status                                     # 各工作树 behind=0
```

### 2. 版本与构建号
- 读 `release.version_source`（如 `app.json` / `Cargo.toml` / `pom.xml` / `package.json`）。
- 版本取"已纳入源码的官方版本"；自定义 label 递增；构建号 +1 且大于旧包。
- 记录：当前版本 / 构建号 / 官方基线 SHA。

### 3. 打包
- 生成型工程用**干净重建**（如 `--clean`），并复核插件/注入确实生效：
  ```bash
  grep -c "<注入标记>" <生成文件>     # 必须 > 0
  ```
- 并发注意：顺序跑构建，避免同时开多个重任务把内存打满。

### 4. 产物核对
```bash
shasum -a 256 <产物>                  # macOS；Linux: sha256sum
ls -lh <产物>                          # 体积与上一代对比，异常波动要能解释
```

### 5. 交付
- 本地/桌面：完整命名的产物 + `.sha256`。
- 共享盘/NAS：**只留一份** `latest`：
  - `<name>-latest.<ext>`（先写临时文件、核对摘要，再原子替换）
  - `<name>-latest.<ext>.sha256`
  - `<name>-latest.txt`（版本、构建号、架构、日期、源码提交 SHA、验证结论）
  - 清理旧的同名产物与旧校验文件；别删其他应用的包。

### 6. 装机核对
```bash
<installer> -r <产物>                  # 保留数据安装
# 核对：版本/构建号/签名；进程 PID 前后是否一致；崩溃日志看时间戳
```

### 7. 推送
```bash
git push --force-with-lease=<ref>:<旧SHA>
```
不用 `--force`；不用 `--admin`、不改保护分支规则。

### 8. 记账
- 更新 `worktree.md`：版本、构建号、产物名、sha256、验证结论、官方基线 SHA。
- 发布说明/交付清单里已出现的 SHA **不要重写那一段历史**。

## 多工作树同一分支（常见坑）

同一分支被多个工作树检出时，不要在 A 工作树里改 B 工作树的文件：

```bash
# 1) 在当前目录建临时迁移分支，完成改动与验证
# 2) 原子更新目标 ref，要求旧 SHA 匹配
git update-ref refs/heads/<branch> <新SHA> <旧SHA>
# 3) 其它工作树先确认干净，再 reset --hard
```

这样不会留下"指针新、文件旧"的假 diff。

## 验收清单
- [ ] 版本/构建号单调递增，且大于设备已装包
- [ ] 产物命名含版本/标签/构建号/日期/架构，附 sha256
- [ ] 共享盘只有一份 latest（包 + sha256 + txt），两处摘要一致
- [ ] 装机后版本/构建号核对通过，数据保留
- [ ] 推送使用 `--force-with-lease` 且旧 SHA 匹配
- [ ] `worktree.md` 已记账

## 反模式
- 用"最新发布标签"当源码版本（源码可能已领先/落后）。
- 构建号不递增 → 装机不更新或降级失败。
- 共享盘堆一堆按日期命名的包，没人知道哪个是最新。
- 把更新检查指向个人仓，或按构建时间判断官方源码新旧。
- 生成型工程用增量构建，插件没注入却以为生效。
- 外部已引用旧 SHA 时重写那段历史。

## 没有这套流程时的最小兜底
至少做到：版本对齐官方、构建号 +1、产物带 sha256、安装用 `-r` 保数据、推送用 `--force-with-lease`。
细节见 `../../references/release.md`。
